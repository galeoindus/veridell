# Audit — 21 November 2026 (v6.10.45)

Scope: the whole shipped site — 22 HTML pages, 41 modules, 13 stylesheets, the
brand asset set and the answer surface. Checks run locally in a headless
Chromium at 320, 360, 390, 430, 768 and 1280 px, plus the repository's own
module check, site audit and 217-test suite.

## Found and fixed

| # | Finding | Where | Fix |
|---|---|---|---|
| 1 | The card's padding had been reset to `0` while the field kept its own inner padding, so the 46 px send circle sat 3 px from the bottom-right corner where the 26 px corner curve cut across it. The arrow was a typed `↑` glyph sitting on the text baseline, not the circle's centre. | `assets/css/mobile.css` | Card padding 12 px, radius 32 px, send circle 44 px inset 13 px from both edges, arrow drawn as a centred masked SVG. Measured: gap 13/13 px, ink centroid 0.33 px from centre. |
| 2 | The contributor and third-party logo wells hid their initials with `:has(img)`, which an older Android WebView or Chrome below 105 does not support — the initials printed through the mark's open centre, so a word appeared behind the logo. | `assets/css/app.css`, `assets/js/views/pages.js` | Hiding now follows the `data-has-avatar` / `has-image` flags the renderer sets, and the flag is set only when a picture has actually loaded. A failed image falls back to the initials instead of an empty circle. |
| 3 | The brand raster set was fourteen hand-exported PNGs from different sources, at different times; the favicon drawing differed from the header mark and the social card carried the old palette. | `assets/img/brand/*`, `favicon.ico` | One master, one producer (`scripts/brand-assets.mjs`): 7 sizes, a maskable icon with the mark inside the 80% safe zone, a root `favicon.ico` (16/32/48, PNG payloads), and a 1200×630 social card built from the same pixels. |
| 4 | The floating Amigo launcher was `display: none` below 860 px, so the only doorway into the assistant disappeared on the device most readers use. Where it did show, it sat on the bottom-right corner and could cover content with no way to move it. | `assets/css/refine.css`, `assets/css/mobile.css`, `assets/js/launcher-drag.js` | Shown on every width, lifted clear of the bottom bar, and draggable up or down. The offset is remembered, clamped back into the viewport on resize or rotation, and double-tap returns it to the corner. A drag never navigates. |
| 5 | Icon stroke weight varied across the set — 1.6, 1.7, 1.8, 1.9 and 1.75 — so rows of icons did not read as one family. | 18 HTML/JS files | One weight (1.75) everywhere; the deliberate 2 (send control) and 2.7/1.3 (placeholder mark) stay. |
| 6 | Multimorphism was repeated inside containers (a card in a card, each with its own blur and shadow) and reached reading surfaces, where the treatment sits between the reader and the text. | `assets/css/refine.css` | One discipline block: the treatment stays on containers (cards, panels, composer, launcher, navigation); nested cards, rows inside a card and every prose surface lose it. Glass panels over content are forced opaque. |
| 7 | The Ask answer page had no sources section, so the page that claims "every answer, with its source" was the one page where the source was not on the page — it was behind an action in the rail. | `assets/js/views/ask.js` | Sources are now part 6 of the answer column, with the licence and revision, before the method note. The answer order is now: evidence → direct answer → key points → topics → facts → sources → method and limits. |

## Checked

- `node scripts/check.mjs` — 41 modules parsed, every import resolves, one version.
- `node scripts/audit-site.mjs` — 47 modules, 22 pages, asset paths and build IDs consistent.
- `node --test test/` — 217 passed, 0 failed.
- Headless Chromium, phone and desktop widths: the home page, the credits page and the composer; no console errors. Send-circle geometry and arrow centroid measured from pixels (13/13 px inset, 0.33 px centroid offset). Launcher drag moves 220 px, persists across a reload, and does not navigate. Credits: initials fall back correctly when an avatar image fails.

## Not checked

- The live site after the Cloudflare Pages rebuild; the sandbox cannot reach `ridellindo.pages.dev`.
- The rendered Ask answer itself. The page reads Wikipedia live, and the sandbox has no network, so the page stopped at its offline state and the new sources block in the answer column was not seen on screen. The code path is the one the article page already uses, but it is unverified here.
- Real Android/iOS devices, Safari, and older WebViews. The `:has()` fallback above is written for those, but it was not run on one.
- Lighthouse / Core Web Vitals.
- The Amigo chat surface (`/amigo/`) beyond its icon and brand assets.

## Known, not changed

- The `amigo/` app ships its own inline styles and a second icon mapper; unifying it onto `assets/js/icons.js` is a separate refactor with its own regression surface.
- The credits page is a very long document on a phone (about 10,000 px). It is readable but would benefit from collapsible sections.
